# 周额度监督算法

Codex Dollar 的周额度监督器回答的是：**按当前观测到的模型组合，这个订阅周额度若全部用完，大约相当于多少官方 API Standard 美元用量？**

它不是 OpenAI 官方公布的固定美元额度，也不代表可退款金额、会员成本或 API 余额。

## 输入信号

监督器只使用本机 Codex JSONL 中已经存在的脱敏信号：

1. `rate_limits.primary` 或 `rate_limits.secondary` 中 `window_minutes = 10080` 的周窗口；
2. 周窗口的 `used_percent`、`resets_at`、`plan_type` 与时间戳；
3. 两个快照之间的 token 用量、模型和服务等级；
4. 仓库内经过官方域名白名单校验的 API 与订阅 credits 价格表。

它不读取提示词、回复正文、API Key、Cookie、`auth.json` 或工作区文件。

## 当前样本

在同一套餐、限额类型和重置窗口中，选择较早的低百分比快照作为基线，选择最新快照作为终点。明确分类为 API Key 的调用会被排除。

设：

- `p0`：基线已用百分比；
- `p1`：最新已用百分比；
- `Δp = p1 - p0`；
- `T`：区间内本地 token；
- `D`：这些 token 按调用日期和模型折算的 API Standard 美元等价；
- `C`：这些 token 按订阅 credits 表折算的 credits。

则：

```text
整周 API 等价 = D × 100 / Δp
整周 credits   = C × 100 / Δp
整周 token     = T × 100 / Δp
剩余 API 等价  = 整周 API 等价 × (100 - p1) / 100
```

只有 `Δp > 0` 且区间内存在本地可计价 token 时才产生美元推算。

## 百分比取整区间

额度百分比通常以整数显示。两个端点各自可能存在约半个百分点的显示误差，因此 `Δp` 约有 ±1 个百分点的不确定性：

```text
保守下界 = D × 100 / (Δp + 1)
保守上界 = D × 100 / (Δp - 1)  # 仅当 Δp > 1
```

当样本仅变化 1% 时不提供稳定上界；2% 的样本仍会有很宽的区间。建议让 App 持续运行，待样本覆盖至少 3%，最好达到 10% 以上。

## 额度重置与并发快照

- `resets_at` 会按 15 分钟粒度归入同一重置窗口，吸收后台返回时间的秒级抖动。
- 百分比下降超过 1 个百分点时开始新的观测段。
- 相差 1 个百分点的短暂下降按整数取整或并发会话旧快照处理，不立即切段。
- 套餐或 `limit_name` 不同的样本不会混合。
- 历史校准只选择与当前套餐一致、价格覆盖率至少 80%、变化至少 3% 且时间不重叠的最近样本。

## 可信度

可信度分数由四部分组成：

- 百分比覆盖量：45%；
- 官方 API 价格覆盖率：25%；
- 本地调用次数：15%；
- 观测时长：15%。

达到 10% 以上百分比变化且价格覆盖率至少 95% 才可能标记为高可信。低可信结果仍会显示，但 UI 会优先展示同套餐历史校准值（如果存在）。

## 无法观测的消耗

官方说明 ChatGPT Work 与 Codex 共享用量，模型、上下文、推理、工具、检索和缓存都会影响消耗，此外还可能有周限额。其它设备、Work、云端任务、图像生成和没有公开 token 单价的功能可能推动百分比变化，却没有对应的本地 token。监督器无法把这些消耗还原成美元，只能在界面中提示局限。

因此，结果适合观察量级、比较模型组合和判断用量速度，不适合财务结算。官方剩余额度仍以 Codex `/status` 或 OpenAI 用量面板为准。

周额度监督始终使用完整的本地快照历史；`scan --since/--until` 只裁剪普通用量报表，不会截断监督器建立基线所需的历史。
