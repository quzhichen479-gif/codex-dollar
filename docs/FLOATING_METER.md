# 悬窗与速度测量

`codex-dollar app --widget` 直接启动桌面悬窗，完整仪表盘也有「打开悬窗」按钮。桌面窗口默认置顶，标题栏可拖动，置顶按钮可切换；右上角箭头打开仪表盘。每种窗口只创建一个，关闭后可以再次打开。关掉全部窗口才结束本地服务。

未安装 `pywebview` 时使用浏览器小窗口。普通浏览器弹窗不能保证跨应用置顶；如被拦截，可允许本地页面弹窗。离线 HTML 不启动实时扫描。

## 三种读数

| 读数 | 计算依据 | 限制 |
|---|---|---|
| 近 60 秒输出 token/s | 时间落在 `(现在−60 秒, 现在]` 的本地 `token_count` 输出增量之和 ÷ 60 | 按落盘时间统计吞吐，包含所有本机会话；不是逐 token 的生成速度 |
| 回合平均 token/s | 最近完整回合输出增量 ÷ 日志 `duration_ms` | 包含首 token 前等待、工具执行和网络时间；不扣除首 token 延迟冒充纯生成耗时 |
| 首 token 延迟 | 完成事件的 `time_to_first_token_ms` | 只在日志提供有效数值时显示，旧版本或未完成回合可能没有 |

输入 token/s 单独统计。输出包含 reasoning token，不能再次相加。累计用量重复快照不重复计数；找不到完整回合起点或首个累计量明显含有此前用量时，不输出该回合平均值。最近模型只说明最后一条用量记录的模型，不能把多会话合计速率归因于该模型。

本地日志和 [App Server 文档](https://learn.chatgpt.com/docs/app-server) 中的用量更新不提供可直接对应每一个 token 的服务端生成时间。即使取得文本 delta，网络分块也不等于 token；可见文本不含全部 reasoning token。当前版本没有精确流式计速接口。若要增加该功能，需要在实际请求链上采集流式事件及可对应的 token 计数，并区分客户端接收吞吐与服务端生成速率；仅提高扫描频率不能补出缺失的信息。

## 额度与刷新

悬窗每次请求完成后等待 2 秒再刷新，避免请求重叠。多个窗口共享 1 秒缓存；扫描器缓存未变化文件的脱敏结果，变化、追加或截断后重新解析。悬窗只计算近 60 秒的金额，不重建全部历史价格报表。页面失败后自动重试，并隐藏当前速率、标记保留的额度信息过时。

额度来自日志里最近的官方快照，不由 token 消耗反算。显示快照时间，超过 5 分钟标为旧快照；到重置时间后显示「待新快照」，不自动补回 100%。缺失窗口、未知百分比和缺失余额不等同于零。Pro 账户不一定有 5 小时窗口，窗口标题按日志实际 `window_minutes` 显示。套餐固定价格和 paid credits 也不等于包含额度。

`--since` / `--until` 只过滤完整历史报告；实时悬窗始终统计现在的本机用量。`--codex-home`、`--active-only`、`--billing-mode` 同时适用于两者。

该功能不读凭据、不改 Codex 配置、不代理请求、不上传日志。`task_complete` 仅保留数值计时字段；回复正文与原始 ID 不进入缓存或 API 响应。
